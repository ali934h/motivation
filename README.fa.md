# Motivation (راهنمای فارسی)

پنل مدیریتی مینیمال و تیره برای مدیریت مجموعه‌ای از کارت‌های انگیزشی. هر کارت می‌تونه یک طرف متن، یک طرف تصویر، یا هر دو داشته باشه، و ترتیب کارت‌ها با درگ‌اند‌دراپ (هم روی دسکتاپ و هم روی موبایل) قابل تغییره.

**استک تکنولوژی:** React + Vite · Cloudflare Pages · Cloudflare Pages Functions · Cloudflare KV · Cloudinary (آپلود بدون امضا)

تمام مراحل دیپلوی این پروژه **کاملاً از طریق داشبورد Cloudflare** انجام می‌شه — نیازی به CLI ابزار `wrangler` یا فایل‌های کانفیگ محلی برای بایندینگ‌ها یا متغیرهای محیطی نیست.

## قابلیت‌ها

- مسیر مخفی: پنل فقط در یک مسیر محرمانه‌ای که خودتون انتخاب می‌کنید فعاله، نه یک مسیر ثابت و قابل‌حدس.
- تنظیم پسورد در اولین بازدید، سپس صفحه ورود؛ پسورد با هش SHA-256 + salt در KV ذخیره می‌شه — هرگز به‌صورت خام ذخیره نمی‌شه.
- کوکی سشن با HttpOnly/Secure/SameSite، به‌همراه محدودیت نرخ ساده بر اساس IP برای تلاش‌های ورود.
- تعداد نامحدود کارت، هر کدوم با طرف متن اختیاری و/یا طرف تصویر اختیاری، که با کلیک/لمس ورق می‌خوره.
- جابجایی کارت‌ها با درگ‌اند‌دراپ که با [`@dnd-kit`](https://dndkit.com/) پیاده‌سازی شده و روی موس و لمس هر دو قابل‌اعتماده.
- آپلود مستقیم تصویر از مرورگر به Cloudinary با استفاده از یک Unsigned Upload Preset (بدون واسطه شدن سرور).

## ساختار ریپو

```
functions/          Cloudflare Pages Functions (بخش API)
  _middleware.js     بررسی مسیر مخفی + بررسی سشن
  _lib/auth.js       توابع کمکی هش پسورد، سشن، rate limiting
  api/auth/          اندپوینت‌های setup، login، logout، session، status
  api/cards/         اندپوینت‌های لیست/ایجاد، ویرایش/حذف، تغییر ترتیب
src/                 فرانت‌اند React
  components/        کامپوننت‌های رابط کاربری (کارت‌ها، گرید، مودال‌ها، فرم‌ها)
  hooks/              useAuth، useCards
  utils/              api.js (واسط fetch)، cloudinary.js (تابع آپلود)
```

## ۱. پیش‌نیازها

- یک اکانت گیت‌هاب که این ریپو در اون پوش شده باشه.
- یک اکانت Cloudflare (پلن رایگان کافیه).
- یک اکانت Cloudinary (پلن رایگان) با یک **Unsigned Upload Preset**.

### ساخت Unsigned Upload Preset در Cloudinary

۱. وارد [داشبورد Cloudinary](https://cloudinary.com/console) بشید.
۲. به مسیر **Settings → Upload** بروید → **Upload presets** → **Add upload preset**.
۳. گزینه **Signing Mode** رو روی **Unsigned** بذارید.
۴. ذخیره کنید و **اسم preset** و همچنین **Cloud name** (که بالای داشبورد نمایش داده می‌شه) رو یادداشت کنید.

## ۲. ساخت KV namespace (از طریق داشبورد Cloudflare)

۱. در داشبورد Cloudflare، به مسیر **Storage & Databases → KV** بروید.
۲. روی **Create a namespace** کلیک کنید، اسمی مثل `MOTIVATION_KV` بذارید و بسازیدش.
۳. نیازی نیست دستی کلیدی اضافه کنید — اپلیکیشن همه‌چیز رو خودش مدیریت می‌کنه.

## ۳. ساخت پروژه Pages و اتصال به گیت‌هاب

۱. در داشبورد Cloudflare، به مسیر **Workers & Pages → Create → Pages → Connect to Git** بروید.
۲. ریپوی `motivation` رو انتخاب کنید و در صورت نیاز دسترسی رو تأیید کنید.
۳. تنظیمات بیلد رو این‌طور مشخص کنید:
   - **Framework preset:** Vite
   - **Build command:** `npm run build`
   - **Build output directory:** `dist`
۴. قبل از اولین دیپلوی، بخش **Environment variables** رو باز کنید (بخش بعدی رو ببینید) و متغیرها رو اضافه کنید — هم برای Production هم Preview.
۵. روی **Save and Deploy** کلیک کنید.

## ۴. تنظیم متغیرهای محیطی (از طریق داشبورد Cloudflare)

به پروژه Pages خودتون بروید → **Settings → Environment variables**، و موارد زیر رو برای **هم Production و هم Preview** اضافه کنید:

| متغیر | مقدار نمونه | توضیح |
|---|---|---|
| `VITE_PANEL_PATH` | `panel-9f2a7c` | یک رشته تصادفی و غیرقابل‌حدس دلخواه انتخاب کنید. به‌عنوان مسیر مخفی URL استفاده می‌شه. |
| `VITE_CLOUDINARY_CLOUD_NAME` | `dxxxxxx` | از داشبورد Cloudinary خودتون. |
| `VITE_CLOUDINARY_UPLOAD_PRESET` | `motivation_unsigned` | اسم Unsigned Preset که ساختید. |
| `PANEL_SECRET_PATH` | `panel-9f2a7c` | **باید دقیقاً برابر** با `VITE_PANEL_PATH` بالا باشه — این مقداریه که سمت سرور توسط API بررسی می‌شه. |
| `SESSION_TTL_SECONDS` | `604800` | اختیاری. طول عمر سشن به ثانیه (پیش‌فرض: ۷ روز). |

> متغیرهایی که با `VITE_` شروع می‌شن در زمان بیلد داخل کد فرانت‌اند قرار می‌گیرن؛ بقیه فقط سمت سرور (Pages Functions) در دسترس هستن. چون متغیرهای Vite در زمان بیلد جاسازی می‌شن، بعد از تغییرشون باید دوباره دیپلوی (یا بیلد جدید) انجام بدید.

## ۵. اتصال KV namespace به Pages Functions (از طریق داشبورد Cloudflare)

۱. به پروژه Pages خودتون بروید → **Settings → Functions → KV namespace bindings**.
۲. روی **Add binding** کلیک کنید.
۳. **Variable name:** دقیقاً `MOTIVATION_KV` بذارید (باید دقیقاً همینو باشه — این اسمیه که داخل کد استفاده شده).
۴. **KV namespace:** namespace ای که در مرحله ۲ ساختید رو انتخاب کنید.
۵. ذخیره کنید. برای اعمال شدن بایندینگ، پروژه رو دوباره دیپلوی کنید (Deployments → Retry deployment، یا یک کامیت جدید پوش کنید).

## ۶. اولین اجرا

۱. به آدرس `https://<your-project>.pages.dev/<VITE_PANEL_PATH>` برید (همون مسیری که در بالا انتخاب کردید — مسیر ریشه `/` عمداً چیز مفیدی نشون نمی‌ده).
۲. چون هنوز پسوردی تنظیم نشده، صفحه **تنظیم پسورد اولیه** رو می‌بینید. یک پسورد (حداقل ۸ کاراکتر) انتخاب کنید.
۳. حالا وارد شدید. اولین کارتتون رو با کاشی **+** اضافه کنید و برای تغییر ترتیب، کارت‌ها رو درگ کنید.
۴. در بازدیدهای بعدی، به‌جای فرم تنظیم پسورد، صفحه ورود رو می‌بینید.

## توسعه محلی (اختیاری)

برای دیپلوی نیازی به این بخش ندارید، ولی اگه خواستید محلی اجراش کنید:

```bash
npm install
cp .env.example .env.local   # مقادیر خودتون رو وارد کنید
npm run dev
```

توجه کنید که Pages Functions (مسیرهای `/api/*`) با اجرای ساده `vite dev` سرو نمی‌شن. برای تست کامل به‌صورت محلی باید از سرور توسعه محلی Cloudflare برای Pages استفاده کنید که خارج از محدوده این راهنمای مبتنی بر داشبورد است.

## نکات امنیتی

- پسوردها با SHA-256 و یک salt تصادفی مخصوص هر نصب هش می‌شن و در KV ذخیره می‌شن؛ پسورد خام هرگز ذخیره نمی‌شه.
- پنل فقط از طریق مسیر مخفی‌ای که تنظیم می‌کنید در دسترسه — هم در مسیر سمت کلاینت و هم از طریق هدر الزامی `X-Panel-Secret` که توسط middleware سمت API بررسی می‌شه.
- کوکی‌های سشن به‌صورت `HttpOnly`، `Secure`، و `SameSite=Strict` تنظیم می‌شن.
- تلاش‌های ناموفق ورود بر اساس IP محدود می‌شن (۵ تلاش در بازه ۱۰ دقیقه‌ای).
